# コミットメッセージ例

## NG → OK 書き換え例

### 新機能

**NG:**
```
✨ [New Feature]: 機能追加
```

**OK:**
```
✨ [New Feature]: ユーザ検索にロール絞り込みフィルタを追加

変更内容:
- GET /api/users に role クエリパラメータを追加
- 検索フォームにロール絞り込みのセレクトボックスを追加

背景:
ユーザ一覧が数千件規模になり、目的のユーザに到達できないという
問い合わせが継続していた。

理由:
サーバ側での絞り込みを選択。クライアント側で絞ると全件取得が前提になり、
大規模テナントで初期表示が実用外になるため。
```

### バグ修正

**NG:**
```
🐛 [Bug fix]: 修正
```

**OK:**
```
🐛 [Bug fix]: Firefox環境でのプロフィール画像アップロード失敗をFormDataのboundary設定漏れで修正
```

### リファクタリング

**NG:**
```
♻️ [Refactoring]: リファクタ
```

**OK:**
```
♻️ [Refactoring]: userServiceの重複バリデーション処理をvalidateUser()に集約しテスト追加
```

### ドキュメント

**NG:**
```
📖 [Doc]: README更新
```

**OK:**
```
📖 [Doc]: 開発環境セットアップ手順にNode 20要件とキャッシュクリア手順を追記
```

## Issue連携の例

### Issue番号を含める場合

```
✨ [New Feature]: #123 ブロックボタンをランキングページに追加

ユーザーをブロックしてコンテンツを非表示にできる機能。
```

### 複数Issueに関連する場合

```
♻️ [Refactoring]: #45 #67 認証ロジックをAuthServiceに集約
```

## 判断基準

迷った場合は以下を基準に:

> 「このコミットをrevertする判断を、ログだけ見て30秒でできるか？」

できなければメッセージを具体化する。subject を具体化しても足りない場合は、
本文（変更内容と意思決定の記録）に理由を書く。

本文の記述例・mode 別の分量の目安は `decision-record.md` を参照。
